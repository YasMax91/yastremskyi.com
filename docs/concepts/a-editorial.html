What does the process actually do?

Pick a task. Risk decides the weight — a typo and a change to VAT do not get the same ceremony. No JavaScript on this page: it is radio inputs and CSS, and it works with scripting disabled.

Choose a task

L0 · Tiny

No spec. No plan. No review agents. No approval. The automatic gates are the entire Definition of Done.

Who reviews

Nobody. This does not need it, and pretending otherwise is how a process stops being used.

What is required

  • The gates that fire on their own

L1 · Small bug fix

A regression test that fails first, then one live exercise of the single thing that was fixed — not a sweep of every consumer.

Who reviews

No agents. A targeted self-trace instead.

What is required

  • Short inline spec
  • Fail-first regression test
  • Live check of the one thing fixed

L2 · Normal feature

Discovery fans out before anything is planned. The blast radius is mapped, not assumed, and the plan is agreed before code exists.

Who reviews

  • impact-mapper — what will this break
  • conformance-reviewer — does the diff satisfy the agreed criteria

What is required

  • Spec, plan, approval
  • Up to 2 rounds of questions
  • Tests written before the code

L3 · High risk

Permissions, migrations, public contracts, financial visibility. Here the intent is challenged, not only the code.

Who reviews

  • impact-mapper
  • blind-spot-map — what did nobody think to ask
  • grounded-researcher — what the provider actually does, with a citation
  • conformance-reviewer
  • adversarial-verifier — is the “it works” claim true

What is required

  • Spec, plan, requirements check, deployment notes
  • Up to 4 rounds of questions
  • An ADR when the decision is cross-cutting

L4 · Critical

Financial calculation, order lifecycle, the permission model, destructive migrations. Human approval is never optional here.

Who reviews

  • Everything L3 engages
  • An adversarial panel — at least two independent skeptics on the riskiest claims

What is required

  • Everything L3 requires
  • Rollback notes
  • Human approval, always

Gates — armed at every level, including L0

  • format on edit
  • static analysis
  • test suite
  • OpenAPI contract
  • enforced runner
  • shipped migrations locked
  • edits locked in discovery
  • unpushed work
  • coverage claim
  • task intent
  • agent contract
The process weight scales with risk. The gates do not — that is the point.

How I work

Three rules I do not bend

Ground it, don’t guess it.

What an external provider does is confirmed against its official documentation with a citation, or it is marked unknown and proven in a sandbox. A plausible answer about someone else’s API is the most expensive kind of wrong.

The spec is the cheap place to be wrong.

Discovery is wide; the change is narrow. One task in three never reaches code because the discussion showed it was mis-scoped, already solved, or cheaper without development.

A claim is not evidence.

Tests, static analysis and contract checks run as gates rather than as good intentions. “It works” gets challenged by a reviewer whose only job is to try to refute it.
