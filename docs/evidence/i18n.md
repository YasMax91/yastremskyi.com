# Evidence — the Ukrainian locale

Measured 2026-08-21. Nothing here is published: every Ukrainian string and every
translated file is unsigned, so the site still renders English on `/uk` and those
pages carry `noindex`.

## Coverage, and the report that lied first

`npm run i18n:coverage` reads the built HTML — the only place a whole page
exists — and reports what is still English on a translated route.

**Its first version said 100% while a reader could still see English.** That is
the worst thing a report can do, and it took Max opening the page to catch it.
Two mistakes, both in the tool:

- It read text nodes only. Attributes a person perceives — `alt`, `title`,
  `aria-label`, the meta description, the Open Graph title and image alt — were
  invisible to it. The portrait's `alt` and one Open Graph `alt` stayed English
  on every Ukrainian page and nothing said so.
- It skipped whole element classes, chips and code, on the theory that they hold
  terms. Some do. But "Idempotency keys", "Accounting and tax export" and
  "Blast-radius discovery before planning" are prose that happened to be rendered
  as chips, and silencing the container silenced them too — 34 capability items
  and 10 stack chips among them.

It now reads text and perceivable attributes and subtracts an explicit list of
strings that stay Latin on purpose, so anything new shows up until somebody
decides otherwise. Proven by injecting each class of regression and watching it
go red: an English `alt`, an English meta description, and an English phrase
inside a chip. A report that has only ever shown 100% proves nothing.

```
████████████████████ 100%  uk            ████████████████████ 100%  uk/status
████████████████████ 100%  uk/about      ████████████████████ 100%  uk/thanks
████████████████████ 100%  uk/groundwork ████████████████████ 100%  uk/work
████████████████████ 100%  uk/notes      ████████████████████ 100%  uk/work/×3
100% translated · 0 English fragment(s) left across uk
```

It excludes what is deliberately English — stack chips, agent and gate
identifiers, install commands, routes, addresses, and the four job titles, listed
by exact string so the list stays something a person can read. A report that can
never reach 100% is a report people learn to skim.

It earned itself immediately: it found that case studies and notes were rendering
their entire navigation, footer and skip link in English, because a formatter had
folded `<Base` onto one line and the locale never reached the layout. Nothing in
the source looked wrong.

## The gate had a hole, and the fonts showed it

The review gate held every UI string from the first commit. It did not hold
**content**: translated markdown rendered straight to the page, so a Ukrainian
case study was live on the home page, unread. The tell was a font request — `/uk`
was fetching `onest-800-cyrillic.woff2` for a page that was supposed to be
English.

Translated files are now reviewed as whole files — a case study is four hundred
words of argument, and splitting it into a table of sentences would make it
unreadable exactly where reading matters — and `forLocale` refuses an unsigned
translation the same way `useTranslations` refuses an unsigned string. After the
fix, the Ukrainian home page contains **zero Cyrillic characters** while
unreviewed, and requests no Cyrillic font.

## What it will cost when it is published

Measured by signing every draft locally and building as it will ship.

|                                          | Document (served) | LCP          |
| ---------------------------------------- | ----------------- | ------------ |
| `/` English                              | 12 722 B          | 1 206 ms     |
| `/uk` while unreviewed (renders English) | 12 985 B          | 1 204 ms     |
| `/uk` published, Cyrillic preloaded only | 14 703 B          | 1 653 ms     |
| `/uk` published, both scripts preloaded  | 14 703 B          | **1 506 ms** |

Preloading both scripts is worth 147 ms and is now what a published Ukrainian
page does: it renders Cyrillic prose _and_ Latin — "Groundwork", "backend",
every stack name — so the Latin faces are needed either way and were otherwise
discovered a round trip late.

**1 506 ms is over this project's 1 300 ms bar, and it is not a defect to fix in
the markup.** Two costs are real and neither is avoidable by being cleverer:

- A bilingual page loads two scripts' worth of fonts — 45.4 KB against 29.9 KB.
- Ukrainian prose is longer, and the document lands at 14 703 bytes against an
  initial congestion window of about 14 600. Trimming 60 bytes moved the number
  not at all; the gap needs ~100 and buys one round trip, ~150 ms, which would
  reach ~1 356 ms and still miss.

So the bar is missed by roughly 200 ms, stated here rather than absorbed. It is a
decision for Max, with three honest options: a separate stated bar for Ukrainian
routes; Latin subsets cut from Ukrainian pages only, which is real work for maybe
10 KB; or dropping a face on Ukrainian pages, which changes the design.

## What the endpoint does now

The contact endpoint answers in the language of the page the form was on, and
sends a visitor without JavaScript to `/uk/thanks` or `/thanks`. The language
arrives on a hidden field, so it selects from a fixed set rather than being
interpolated into a path — a forged value cannot bounce anyone off this site with
its own domain in the address bar, and cannot inject a header. Nine new tests
cover it, including the hostile values.
